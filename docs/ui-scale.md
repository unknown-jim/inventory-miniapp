# 操作界面字号、热区和密度

给店主看、点。送货单是给客户看的单据版式，不走这套。

## 本次改版废止了什么

2026-08-26 起，**本文档原先的「正文 36rpx / 可点高度 96rpx」一档已废止**。

原规则的依据是工信部适老化「正文不小于约 18px」。废止理由：

- 18px 基数在微信「关怀模式」1.4 倍下会把销售页撑破——这个隐患原文档自己记着，但当时的解法是「不跟关怀模式改 rem」，等于把问题挂起。基数降到 14px 后，1.4 倍是 19.6px，撑破的风险消失。
- 现有 `--fs-xs / --fs-sm / --fs-md` 三档只差 1px（32/34/36rpx），层级形同虚设，副信息和正文分不出主次。

**没有废止的是可点热区 44pt 这条。** 它来自[小程序适老化设计指南](https://developers.weixin.qq.com/miniprogram/design/elderly.html)（微信官方，可点热区至少约 44pt），是外部标准不是本仓库自定的档位，继续作为地板。

## 字号

按 375 宽屏设计，`1px = 2rpx`。变量写在 `app.wxss` 的 `page {}` 里，页面只消费。

| 变量 | rpx | ≈px | 用途 |
|---|---|---|---|
| `--fs-caption` | 24rpx | 12 | 角标、tag 文字、时间戳 |
| `--fs-label` | 26rpx | 13 | 字段标签、行内副说明 |
| `--fs-body` | 28rpx | 14 | 正文、输入框、列表主文案 |
| `--fs-title` | 34rpx | 17 | 卡片标题、页内区块标题 |
| `--fs-amount` | 32rpx | 16 | 列表行金额 |
| `--fs-amount-lg` | 40rpx | 20 | 汇总块金额 |
| `--fs-display` | 48rpx | 24 | 客户欠款、单据合计 |
| `--fs-hero` | 80rpx | 40 | 看板首屏大数字 |

旧的 `--fs-xs / sm / md / lg / xl` 保留为别名过渡，新代码不要再用。

原生 tabBar 的标签由微信平台渲染（约 10–11px），不在 `--fs` 体系内，不受 `--fs-caption` 地板约束；设计稿按原生惯例还原即可，实现侧也没有覆盖入口。这是 12px 地板的唯一豁免。

### 金额按位数自动降档

真实店铺应收已到 549 万，`¥5,490,000.00` 是 13 个可见字符。大号金额必须按长度降档，**不换行、不截断、不缩放**：

| 位置 | 可见字符数 | 用哪一档 |
|---|---|---|
| 看板 hero | ≤10 | `--fs-hero` 80rpx / 40px |
| | 11–13 | `--fs-hero-md` 68rpx / 34px |
| | ≥14 | `--fs-hero-sm` 56rpx / 28px |
| 半宽统计块 `.stat-num` | ≤9 | `--fs-amount-lg` 40rpx / 20px |
| | ≥10 | `--fs-amount-lg-sm` 32rpx / 16px |
| 列表行金额、客户欠款红字 | 任意 | 不降档，现有字号够用 |

「可见字符数」= `util.money()` 输出加上 `¥` 后的 `length`，含千分位逗号和小数点。

落地方式：在 JS 里按字符串长度挑 class（`amount-hero` / `amount-hero-md` / `amount-hero-sm`），**不要用 CSS `transform: scale` 或 fit-text 之类的运行时缩放**——那会让同屏金额的视觉字重不一致，而且在 rpx 布局下容易半像素模糊。

## 热区

| 变量 | rpx | ≈px | 用途 |
|---|---|---|---|
| `--tap-min` | 88rpx | 44 | **一切可点元素的地板**：chip、stepper 加减、列表行内按钮、图标按钮、× 删除 |
| `--tap-md` | 96rpx | 48 | 输入框、次级按钮、可点列表行 |
| `--tap-lg` | 104rpx | 52 | 主按钮、底部固定 CTA |

`--chip-min` 并入 `--tap-min`，不再单列——胶囊是规格选择的唯一输入方式，不能比别的可点元素矮。

视觉尺寸可以小于热区，用透明 padding 撑开：页头齿轮视觉 40rpx、热区 88rpx；行尾 × 视觉 28rpx、热区 88rpx。**视觉小、热区不小。**

## 密度规则（全站同一套）

- **数字块最多两列。** 看板和流水汇总用 `.stat-grid`（2×2）。真实店铺应收已到 549 万，排版按 `¥5,490,000.00`（13 字符）对，不是按 `¥9999.99` 对；超长走上面的自动降档。
- **并排操作最多三等分，允许折行。** 用 `.action-strip`。四字按钮用正常左右 padding，`white-space: normal`；窄屏用 `flex-basis` 折行，不缩小字号。
- **表单并排最多两格**（数量|单价）。用 `.field-row` + `.half`，间距走 `--gap`。
- **筛选项、规格 chip 一律折行**，高度不低于 `--tap-min`，不把字改小。用全局 `.chips` / `.chip`。唯一例外：**流水页类型筛选**——类型有 7 种、是低频辅助，折行要占两行并把列表首屏挤掉；允许一行横滑 + 右缘渐隐（渐隐承担「还有更多」的可发现性），单项高度仍不低于 `--tap-min`。
- **chip 的颜色对应可点性，这条是铁律**（见下节）。
- **输入框下的快捷胶囊**要让人知道点了会怎样。经手人用 `.field-hint`（「点选本店成员，也可手写」）。空称呼不要写「未命名」：有名字用名字，当前自己用「我」，别人用「店主 / 店员」。
- **分段开关最多 3 项**（入库|出库、普通|待加工|分规格现货）。用 `.seg` + `.seg-item`。分段开关只装互斥的档位；要填的是金额就用输入框加快捷胶囊，别拿两个档位去替代（销售的实收就是这么从「现结|赊账」改过来的）。
- **列表行** 左名称+说明、右标签/金额；金额按现有 `util.money` 两位小数，右栏按 `¥5,490,000.00` 的宽度排，不截断。
- **数量一律可直接输入。** 步进器只是辅助，中间的数字必须可点开输入框，且容器按四位数排宽。销售、进货、退货、盘点、换规格五处统一。
- **商品目录两列图卡。** 商品 tab 一行两个：上图、下名称 / 规格数与库存 / 起价。点卡片进**详情**（只读），从详情右下角进编辑——列表直接进编辑容易误改。

## chip 的颜色铁律

一个 chip 长什么样，必须能推出它能不能点。全站只有这四种：

| 视觉 | 含义 | 能点吗 |
|---|---|---|
| 灰底灰字 | 未选中 | 能 |
| 白底黑描边 | 已选中 | 能 |
| 彩色浅底 + 同色深字 | **状态标识**（半成品、低库存余量、类型角标） | **不能** |
| 灰底 45% 透明 | 禁用 | 不能 |

推论：流水页的类型筛选 chip 选中态用**白底黑描边**，不用类型色浅底——类型色浅底在这套规则里已经被「不可点的状态标识」占住了。类型色只出现在 tag 上。

## 新页面要

1. 根节点 `class="page"`
2. 能套共用类就套，不要在页面 wxss 里再定义 `.field-row` / `.stat-grid` / `.mask` / `.sheet`
3. 字号和可点高度用上面的变量，不要写死小于 `--fs-caption` 的字、不要写小于 `--tap-min` 的可点高度
4. 破坏性动作用 danger 视觉，且危险等级越高视觉越强——不要出现「移出店员是红字、清空整店账本是灰描边」这种倒挂
5. 错误文案走 `utils/messages.js`，不要在页面里自己写。可重试和不可重试是**两种**错误态：不可重试的那种不给重试按钮

## 不要做

- 不要为了跟微信「关怀模式」把全站改成 rem。当前布局按 rpx 排。
- 不要把送货单 `components/slip-overlay/index.wxss` 和画布导出字号套进这套变量。
- 不要再做「标准 / 大 / 更大」三档缩放，不要挂缩放 behavior。
- **不要改原生导航栏 / tabBar。** 这条继续有效：本次改版走的是降级导航方案——原生 tabBar 收敛到 4 个（看板 / 商品 / 流水 / 客户），「记一笔」用看板首屏主按钮 + 流水页 FAB 承载，不做自定义 tabBar 的中央凸起，页头右上不放主动作（那里是微信胶囊的位置）。
