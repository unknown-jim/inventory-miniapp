# 操作界面字号、热区和密度

给中老年店主看、点。送货单是给客户看的单据版式，不走这套。

## 依据

- [小程序适老化设计指南](https://developers.weixin.qq.com/miniprogram/design/elderly.html)（微信官方：正文随字号放大，可点热区至少约 44pt）
- 工信部适老化常见要求：正文不小于约 18px（本仓库按 375 宽屏约 36rpx 来对）

下面的「必须」以这两处为准。档位按本仓库形态推导：单人记账小程序、使用者多为店主、销售页字段密。只锁一档，不跟微信关怀模式改 rem（销售页会被撑破）。

## 怎么做

操作页只有一种大小，锁在原先的「大」：正文 36rpx、标签 32rpx、主按钮约 112rpx。字号、热区和间距写在 `app.wxss` 的 CSS 变量里，页面只消费共用布局类。

| 变量 | 含义 |
|---|---|
| `--fs-xs` | 标签、角标 |
| `--fs-sm` | 次要说明、筛选项 |
| `--fs-md` | 正文、输入 |
| `--fs-lg` | 标题、主按钮文字 |
| `--fs-xl` / `--fs-hero` | 金额、看板数字 |
| `--tap-sm` / `--tap-md` / `--tap-lg` | 可点控件高度 |
| `--chip-min` | 胶囊选项最小高度 |
| `--space-xs` … `--space-xl` | 间距 |
| `--page-pad` / `--card-pad` | 页面、卡片内边距 |
| `--gap` | 横排缝（动作条、表单行、chip） |

密度规则（全站同一套）：

- **数字块最多两列。** 看板和流水汇总用 `.stat-grid`（2×2）。`¥9999.99` 在四列里放不下。
- **并排操作最多三等分，允许折行。** 用 `.action-strip`。四字按钮用正常左右 padding，`white-space: normal`；窄屏用 `flex-basis` 折行，不缩小字号。
- **表单并排最多两格**（数量|单价）。用 `.field-row` + `.half`，间距走 `--gap`。
- **筛选项、规格 chip 一律折行**，高度不低于 `--chip-min`，不把字改小。用全局 `.chips` / `.chip`。
- **输入框下的快捷胶囊**要让人知道点了会怎样。经手人用 `.field-hint`（「点选本店成员，也可手写」）。空称呼不要写「未命名」：有名字用名字，当前自己用「我」，别人用「店主 / 店员」。`.field-input + .chips`、`.axis-title + .chips`、`.field-hint + .chips` 把胶囊和上方输入分开，不要只写下边距。
- **分段开关最多 3 项**（入库|出库、普通|待加工|分规格现货）。用 `.seg` + `.seg-item`。高度 `min-height: var(--tap-sm)`，文案可折行，字号不低于 `--fs-sm`。分段开关只装互斥的档位；要填的是金额就用输入框加快捷胶囊，别拿两个档位去替代（销售的实收就是这么从「现结|赊账」改过来的）。
- **列表行** 左名称+说明、右标签/金额；金额按现有 `util.money` 两位小数，右栏按这个宽度排，不截断。

新页面要：

1. 根节点 `class="page"`
2. 能套共用类就套，不要在页面 wxss 里再定义 `.field-row` / `.pay-tabs` / `.stat-grid`
3. 字号和可点高度用上面的变量，不要写死小于 `--fs-xs` 的字、不要写小于 `--tap-sm` 的可点高度

## 不要做

- 不要为了跟微信「关怀模式」把全站改成 rem。当前布局按 rpx 排，跟系统 1.4 倍容易把销售页撑破。
- 不要把送货单 `components/slip-overlay/index.wxss` 和画布导出字号套进这套变量。
- 不要再做「标准 / 大 / 更大」三档缩放，不要挂缩放 behavior，不要改原生导航栏 / tabBar。
